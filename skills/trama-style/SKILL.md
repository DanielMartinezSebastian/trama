# Aplicar una dirección visual

Resuelve la versión del consumidor con `node <directorio-de-esta-skill>/scripts/context.mjs --cwd <proyecto>`. Consulta el índice y la guía de esa instalación. Cada guía tiene ficha en `knowledge/guides/<id>` con tokens, fuentes y una tabla de contraste medida; úsala para decidir qué roles sirven para texto. Receta, piezas y ejemplos selectivos son solo los de salon. No copies valores de `main` a una dependencia antigua.

Elige por público, contenido y acción principal; conserva una guía/adaptación ya definida salvo que el encargo pida cambiarla. Una guía es más que paleta: escala y peso tipográfico, espacio, medida de lectura, superficies y ritmo de movimiento. Aplica `GuideFrame` y clases `ui-g-*` donde corresponda, más `variant` en las piezas; tokens en un contenedor no rediseñan automáticamente su composición.

Comprueba fuentes disponibles y su carga. `trama-ui/fonts` depende de la transformación `next/font`; sigue la configuración comprobada del contexto. Las familias Fontshare no son archivos incluidos; declara sustituciones. Si una referencia externa determina la dirección, separa observación, inferencia y decisión; el [formato de brief](../trama-research/references/brief.md) es opcional si esa skill está instalada.

Propón una muestra representativa antes de extender una adaptación global. Revisa titulares y texto largo, botones, formularios y estados en móvil/escritorio. **El contraste es una puerta de salida:** mide cada pareja real de texto/fondo, no solo los tokens de `GuideFrame`: fondo de página, tarjetas, alertas, badges, campos, estados, pies, CTA y capas sobre imagen, en reposo, hover, foco, seleccionado, deshabilitado y error. Exige 4,5:1 para texto normal; 3:1 solo para texto grande (≥24 CSS px o ≥18,66 px en negrita) y componentes gráficos. En este repo, ejecuta `npm run qa:contrast -- <url-local> --widths 320,390,556,700,768,830,1024,1072,1150,1440,1920` en cada ruta: debe haber **cero incumplimientos**. Repite axe dentro del recorrido Playwright después de activar estados que no aparecen al cargar. `qa:contrast` deja como pendientes las parejas sobre gradientes, imágenes o capas que axe no puede medir: no cuentan como aprobadas; mira el texto en la captura real y añade una superficie/scrim opaco que garantice el contraste en todo el bloque, o mide muestras claras y oscuras del fondo. No uses una sombra para reparar contraste. Como base de composición, texto informativo ≥16 px, secundario ≥14 px y metadatos funcionales ≥12 px; baja de ahí solo para una etiqueta realmente decorativa, tras revisar su lectura a escala real.

En una petición de varias versiones de un mismo proyecto, separa lo que la marca exige de lo que solo sugiere. No asignes la misma guía de estilo a todas por comodidad: cada versión puede elegir guía, adaptación local o una dirección propia compatible con sus restricciones. Las guías y recetas sectoriales son fuentes de decisiones, no plantillas ni cuotas estéticas.

Propón direcciones conceptuales a partir del contenido y la audiencia; evita empezar siempre por una landing corporativa o por una lista fija (editorial, SaaS, evento…). Cuando el usuario pida tres o más opciones, explora más candidatas de las que vas a presentar y elige las que se distingan en sus ejes libres: premisa, estructura, interacción dominante, composición/ritmo, jerarquía tipográfica, navegación y tono visual. Conserva los colores/logos requeridos; si el usuario permite salir de la marca, trata sus colores como inspiración parcial y no como una paleta cerrada. Las opciones deben ser sistemas expresivos distintos, no skins sobre la misma maqueta. Compara capturas iniciales lado a lado. Al iterar sobre la elegida, no cambies los rasgos que el usuario ya aprobó sin motivo.

`GuideFrame textContrast` solo ajusta `--mut-text`/`--acc-text` para texto del kit sobre su `--bg` opaco. No certifica CSS propio, superficies anidadas, imágenes, transparencia, estados ni tokens originales. Para CSS propio parte de `var(--mut-text, var(--mut))` y `var(--acc-text, var(--acc))`, y mide de nuevo contra el color que queda detrás. Si el par falla, oscurece/aclara el texto o la superficie; no compenses con peso tipográfico ni tamaño. Registra excepciones únicamente para texto decorativo prescindible, nunca para contenido o acciones.

Revisa explícitamente todos los textos visibles en las capturas y en el navegador, no solo `h1`, párrafos y controles: las etiquetas de composición suelen vivir en `span`, `div`, SVG o capas posicionadas, y pueden usar escritura vertical, rotación o transformaciones. Clasifica cada solapamiento por su efecto, no solo por la geometría: capas de foto/titular, tipografía de cartel o elementos decorativos detrás del contenido pueden ser decisiones estéticas válidas; un solapamiento deja de ser válido si tapa texto, confunde qué elemento pertenece a qué bloque, debilita el orden de lectura o dificulta usar un enlace/control. La legibilidad del texto informativo y de las acciones prevalece sobre el efecto. Revisa también microtexto y coordenadas sobre imágenes/ilustraciones: que sean decorativos no evita comprobar tamaño, contraste y lectura al tamaño real.

No valides responsive con solo un ancho móvil y uno de escritorio. Prueba extremos y cambios de composición: 320, 390, 768, 1024 y 1440 px, más el ancho exacto de cada captura/referencia y al menos un ancho a cada lado de los breakpoints CSS que cambien columnas, posición, tamaño o visibilidad. Si la captura incluye el navegador o tiene escala/zoom, confirma el viewport CSS real; distingue resolución de pantalla de ancho CSS y prueba el ancho completo (por ejemplo, 1920 px en un escritorio 1080p). Añade anchos intermedios donde las columnas aún caben, pero el texto ya no. En este repo, `npm run qa:visual-text -- <url> --widths 320,390,556,700,768,830,1024,1072,1150,1440,1920` captura y compara cajas de todos los nodos de texto renderizados, incluidos `span` y `div`, y marca pares de bloques próximos y textos que rebasan el borde de su caja flex/grid; úsalo como detector de candidatos junto con la inspección visual. Revisa especialmente marcas e índices contra líneas divisorias y kickers de columnas vecinas: una palabra puede cruzar una regla o invadir otra columna aunque no choque con otra caja de texto, sobre todo con cursivas, tracking negativo o una columna demasiado estrecha. Inspecciona titulares, subtítulos, etiquetas sobre imágenes, navegación y CTA en esas capturas; corrige encuadre, separación, fondo o tamaño si hace falta. Distingue en la entrega las capas intencionales de cualquier interferencia que siga afectando lectura. La geometría automática sirve para señalar candidatos, pero no decide por sí sola si el solapamiento es intencional o legible.

Decide si una imagen raster aporta algo concreto a la dirección visual. Para una foto, ilustración o textura original, prepara un brief con sujeto, tono, encuadre, proporción y paleta; si el cliente actual ofrece generación de imágenes (por ejemplo, Codex imagegen), puedes usarla. Es opcional: no la supongas disponible ni fuerces imágenes donde basten componentes, SVG o CSS. Evita texto y logotipos incrustados salvo que el usuario los haya proporcionado. Revisa el resultado y su recorte en los tamaños de uso.

Conserva la identidad elegida entre rutas y estados. Entrega la decisión y sus fuentes junto a capturas e inspección visual; una puntuación de afinidad no sustituye revisión humana ni acredita funcionalidad.
